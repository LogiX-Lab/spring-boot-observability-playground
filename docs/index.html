How each component is wired to emit traces

order-front  Next.js Node.js

// instrumentation.node.ts
import { NodeSDK } from "@opentelemetry/sdk-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";
import { HttpInstrumentation } from "@opentelemetry/instrumentation-http";
import { UndiciInstrumentation } from "@opentelemetry/instrumentation-undici";

process.env.OTEL_SERVICE_NAME ??= "order-front";

const sdk = new NodeSDK({
  traceExporter: new OTLPTraceExporter({ url: "http://localhost:4318/v1/traces" }),
  instrumentations: [
    new HttpInstrumentation(),   // inbound HTTP spans
    new UndiciInstrumentation(), // outgoing fetch() → order-service
  ],
});
sdk.start();

Spring Entity N+1 Problem

Order ↔ OrderItem — as found in this project

The Root Cause — FetchType.EAGER

// OrderEntity.java — line 41
@OneToMany(mappedBy = "order",
           cascade = CascadeType.ALL,
           fetch = FetchType.EAGER)  ← triggers N+1
private List<OrderItemEntity> items = new ArrayList<>();

SQL Emitted for getOrders(customerId)

  • 1SELECT * FROM orders WHERE customer_id = ? ORDER BY created_at DESC
  • NSELECT * FROM order_items WHERE order_id = 1
  • NSELECT * FROM order_items WHERE order_id = 2
  • NSELECT * FROM order_items WHERE order_id = 3
  • NSELECT * FROM order_items WHERE order_id = …

With N orders in the result → N + 1 database round-trips

Solutions — Best to Quickest Fix

A — EntityGraph 1 JOIN query · cleanest approach 
// OrderEntity.java — change EAGER → LAZY
fetch = FetchType.LAZY

// OrderRepository.java — annotate query methods
@EntityGraph(attributePaths = "items")
List<OrderEntity> findByCustomerIdOrderByCreatedAtDesc(Long customerId);
@EntityGraph(attributePaths = "items")
List<OrderEntity> findAllByOrderByCreatedAtDesc();
B — @BatchSize one-liner · ceil(N/50) queries 
# application.properties — global batch fetch
spring.jpa.properties.hibernate.default_batch_fetch_size=50

// Replaces N queries with batched IN clauses:
// SELECT * FROM order_items WHERE order_id IN (1,2,...,50)
C — JOIN FETCH JPQL 1 JOIN query · explicit control 
@Query("SELECT DISTINCT o FROM OrderEntity o " +
       "LEFT JOIN FETCH o.items " +
       "WHERE o.customerId = :id ORDER BY o.createdAt DESC")
List<OrderEntity> findByCustomerIdWithItems(@Param("id") Long id);
